# Усиление безопасности 0.2.9 — 14.10.2026

Область: локальное Windows-приложение, импорт резервных копий, Electron IPC, внешние ресурсы, архив приложения и обновления. Серверная CRM, логин и роли в этот этап не входят: в текущей программе нет серверной админки или серверных сессий.

## Исправления

| Сценарий | Защита |
|---|---|
| Резервная копия подставляет ID существующего проекта | Импортирует отдельную копию; переназначает ID исходников и источник геометрии в одной транзакции. Оригинал сохраняется |
| Чужое окно/кадр вызывает системные функции | Проверяется экземпляр webContents, главный frame, точный URL страницы и состояние окна |
| Переход к служебному ресурсу или другому сайту | Навигация разрешена только на главную страницу приложения; внешнее окно всегда запрещено. Фиксированная ссылка компании открывается системным браузером |
| HTML/скрипт в названии клиента или справочном изображении | React выводит текст; CSP запрещает встроенные скрипты и обработчики, iframe и формы |
| Скрытая сетевая отправка или запрос к локальному сервису из окна | CSP и session.webRequest запрещают HTTP(S), WS(S), FTP и file. Внешние изображения не загружаются; локальные изображения работают |
| Загрузка постороннего файла | Разрешены только Blob из origin приложения с системным диалогом сохранения |
| Запуск EXE как Node или внедрение NODE_OPTIONS | Соответствующие флаги Electron выключены в бинарнике |
| Подмена app.asar или обход через resources/app | ASAR integrity и OnlyLoadAppFromAsar включены; дополнительные привилегии file:// выключены |
| Подмена файла обновления | Сохранена проверка SHA-512, стабильного выпуска и сохранения проекта перед установкой |

Обновления используют отдельную сессию electron-updater: сетевой запрет окна не относится к этому каналу. Предыдущие резервные копии version 1 сохраняют совместимость; повторный импорт создаёт копию вместо скрытой перезаписи. Для референса из старой резервной копии с HTTPS-адресом требуется загрузить файл изображения — запись и подпись референса сохраняются.

## Проверки перед выпуском

- Unit: чужой sender/frame/URL, уничтоженный frame, скачивание из другого origin, некорректные JSON/контуры/размеры, конфликт ID проекта и исходников, контрольная сумма обновления.
- Browser UI: HTML в импортированном имени остаётся текстом; повторный импорт сохраняет исходный проект.
- Готовый Windows EXE: CSP блокирует скрипт и onerror; сетевые запросы к синтетическому localhost не доходят до сервера, в том числе из окна без CSP; чужое окно не вызывает PDF/скачивание/установку; -e/ELECTRON_RUN_AS_NODE/NODE_OPTIONS не выполняют тестовый код; повреждённый archive вызывает integrity error.
- Обязательные прежние проверки: PDF, 3D, резервные копии, сохранение перед закрытием и настоящий переход на новую установленную версию.

Локально проверены типы, 30 целевых тестов и npm audit (0 известных уязвимостей на момент проверки). В 285 отслеживаемых рабочих файлах не найдены ключи по шаблонам приватного PEM, GitHub PAT и OpenAI project key. Это поиск по шаблонам текущих файлов, не доказательство отсутствия любого возможного секрета и не аудит всей истории Git. Итог Windows-проверок фиксируется в workflow Windows application для коммита выпуска; публикация зависит от успешной проверки EXE и интерфейса.

## Ограничения

- Это защита от конкретных проверенных сценариев, а не сертификат независимого пентеста.
- Установщик пока без цифровой подписи Windows. Проверка ASAR не защищает от противника, который может одновременно заменить EXE и archive или управляет компьютером как администратор. Для коммерческого выпуска нужен сертификат подписи.
- Проекты находятся в IndexedDB текущего пользователя Windows и не зашифрованы отдельным ключом приложения. Пользователь той же Windows-учётной записи может получить к ним доступ. Локальный пароль в JavaScript не обеспечит разделение менеджеров: для него нужна серверная авторизация и проверка прав на сервере.
- Отладка main-процесса через явные CLI inspect-аргументы пока сохранена для автоматизации Windows QA. По умолчанию отладочный сервер не запускается. Её отключение требует переноса QA на отдельный способ управления; наличие доступа к запуску EXE и файлам этой Windows-учётной записи выходит за границу защиты от чужих резервных копий и веб-контента.
- Код JavaScript доступен для изучения; секреты и полномочия сервера нельзя хранить в нём. Сейчас серверных административных ключей в приложении нет.
