# Первая правка растровых зон — 03.10.2026

Рабочая ветка: `claude/festive-turing-m7na3z`. Родитель публикации:
`5ce1b50d0eef36b2ea610624d734c70efb96a285`. Версия распознавания:
`monochrome-zones-v7`; Git blob алгоритма: `64904e0a5c591475fe006626a157b88c042e6386`.
Это промежуточная правка, а не завершение ТЗ и не обучение весов модели.
Примеры используются для диагностики и регрессии; правил по имени примера нет.

## Изменения

- На монохромном плане тонкие светлые размерные линии не дробят поиск
  затравок комнат, если обнаружено различие толщин штрихов. Толстые светлые
  и тонкие тёмные линии сохраняются; исходная маска остаётся для границ и проёмов.
  Цветные заливки и преимущественно цветные стены исключены из этого правила.
- Пространственная группа соседних областей позволяет исключить отдельно
  стоящий штамп/таблицу. Это фильтр, не расширение рамки квартиры.
- Предположение масштаба по типовой ширине использует почти прямоугольные
  комнаты; рамка Г-образного коридора больше не считается его шириной.
  Масштаб без введённой площади остаётся оценочным.
- Перекрытия после независимого сглаживания контуров устраняются по владельцу
  пикселей до сглаживания. Вырез разрешён только при сохранении одного кольца
  и минимальной площади. Если нужны отверстие или разрыв комнаты, оба контура
  сохраняются, а отчёт распознавания содержит замечание для проверки.

Новых зависимостей, внешних сервисов, схем хранения и миграций нет. Редактор,
сохранение пользовательских исправлений и векторный путь не изменены.
WIP `color-first.patch` не интегрирован; `rect-walls.patch` не применялся.

## Измерения

Core, эталоны площадей, SHA-256 входов и порог сохранены. Бенч прошёл на 33
планах за 293,66 с: `0.8792958873172777` против `0.8691096089491812`.
Это существующая метрика площадей/количеств/входа, не IoU и не точность назначения.
Готовых вариантов мебели по существующему валидатору: 2,36 против 2,09;
полных вариантов: 0,85 против 0,76. Это не подтверждает правильность геометрии.

Пары перекрытий больше 0,0001 м²: **44 → 2**; зон с неположительной площадью
или нечисловыми координатами: **0**. Остались net16 (зоны 6/9, 1,457193 м²)
и net27 (4/7, 2,005226 м²): безопасный вырез невозможно представить текущим
однокольцевым контуром. Площади здесь зависят от масштаба алгоритма.

| Пример | Балл до | Балл после | Зон до / после | Оценка |
|---|---:|---:|---:|---|
| net03 | 95,45 | 90,00 | 9 / 10 | Регрессия метрики площади; требует разметки и проверки, не скрыта средним |
| net05 | 83,33 | 92,86 | 6 / 6 | Улучшение текущей метрики |
| net10 | 95,45 | 100,00 | 7 / 8 | Улучшение текущей метрики, полные контуры ещё не размечены |
| net24 | 75,00 | 100,00 | 8 / 8 | Улучшение текущей метрики |
| net15 | 100,00 | 100,00 | 7 / 7 | Устранены два перекрытия санузлов с коридором, скос балкона сохранён |

Все 20 изменённых core-результатов перечислены в
`bench/diagnostics/monochrome-zones-v7-comparison.json`. Для каждого подготовлены
JSON, изображения до/после с номерами, оценочными площадями, версией и
контуром без исходника. Комплект сравнений передан пользователю отдельно;
клиентские изображения в публичный репозиторий не добавлены.

На новом пользовательском №13 большая комната снизу слева теперь выделяется.
Зон 8 → 6, перекрытий 3 → 0. Мелкие помещения и балкон по-прежнему
распознаются неверно; проёмы также ненадёжны (6 дверей, 15 окон).
Эталон контура не согласован, площадь из легенды не использована как калибровка.
На №07 устранено одно перекрытие, но система по-прежнему выбирает правый
рисунок из двух: нужны явный выбор фрагмента/детекция отдельных планов.

## Проверки и воспроизводимость

Node 24.19.0, npm 11.9.0; SHA-256 `app/package-lock.json`:
`587fe0ffff60730d1c4624e78b6b8ee6806abf558816cbfcc608bfdfce064c72`.
Геометрия детерминирована; идентификаторы приложения используют время/случайность,
диагностический экспорт перенумеровывает зоны. Seed алгоритму не передаётся.
Метаданные версии и результаты каждого плана сохранены рядом с comparison JSON.

Из `app/`:

```sh
npm run typecheck
npx vitest run --exclude tests/bench.test.ts
npm run build
npm run bench
npx playwright test --reporter=json
PLAN_DIAGNOSTICS=/tmp/trust-zones-v7 PLAN_SOURCE_SHA=5ce1b50d0eef36b2ea610624d734c70efb96a285 PLAN_RECOGNITION_VERSION=monochrome-zones-v7 npx vitest run tests/diagnostics.test.ts
```

Из корня: `python3 scripts/render_diagnostics.py /tmp/trust-zones-v7`.
Для частных новых входов дополнительно задать `PLAN_DIAGNOSTIC_INPUT` и
`PLAN_DIAGNOSTIC_COUNT=2`; структура — каталог примера с plan.jpg и truth.json.

Типы и сборка проходят; unit **47 passed / 26 skipped**; e2e **5 passed /
5 skipped**, неожиданных ошибок и flaky нет. Новые unit проверяют покрытие
известных точек комнаты с размерной сеткой, сохранение границ, исключение
отдельного служебного блока и net15 (семь зон, отсутствие перекрытий, скос).
Два теста размерной сетки воспроизводят ошибку исходного алгоритма.
Таймаут реального net15 — 30 с из-за параллельной нагрузки, а не бюджет продукта.
Полный экспорт 33 планов и отдельный экспорт двух новых входов проходят.

В этой среде Playwright использовал Chromium вне зависимостей проекта:
`FONTCONFIG_PATH=/tmp/trust-browser-assets/fonts LD_LIBRARY_PATH=/tmp/trust-browser-assets PW_CHROMIUM=/tmp/trust-chromium`.
Сохраняются прежние предупреждения о размере bundle и повторном React-ключе
замечания про раковину. Пропуски тестов объяснены исходным аудитом.

## Оставшиеся ограничения и следующий шаг

ТЗ полностью не принято: нет согласованных геометрических эталонов, измерений
IoU, топологии и назначения; PDF/векторный путь этой правкой не оценены.
Существующие неверные количества зон и проёмов в наборе остаются. Регрессия
net03 требует отдельного решения до итоговой приёмки. Две неоднозначные пары
перекрытий не устранены. Время измерено в общем контейнере при параллельных
прогонах, не на целевом телефоне; мобильный бюджет и память не установлены.

Следующий технический шаг — разобрать маленькие помещения и балкон №13,
подготовить контурную разметку №13 и net03 для согласования, затем исправлять
общую причину потерь и ложных проёмов. Пользователь должен проверить показанный
результат; снимок текущего алгоритма не выдаётся за верное разделение всей квартиры.
