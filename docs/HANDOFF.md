## Что за проект

«ТРАСТ РЕМОНТ» — планировщик квартиры (`app/`, Vite + React + TypeScript). Работает так:

1. Загружается план БТИ: PDF, скан или картинка.
2. Программа находит помещения, двери и окна.
3. Программа строит 3 варианта расстановки мебели.

Конечная цель пользователя: **любой план БТИ → верные зоны → автоматическая расстановка
мебели**. Неточности правятся «Быстрой правкой плана» на экране вариантов.

Пользователь пишет по-русски, работает с телефона.

**Формат ответов**, по его настройкам — «Консилиум экспертов»:
- Строгий Критик, Опытный Архитектор и Прагматик спорят между собой;
- в конце — «Финальный вердикт Судьи»;
- коротко, без поддакивания, честно о провалах.

## Как пользователь хочет работать

- После каждой правки:
  - прогнать бенч;
  - прислать картинки «как программа разделила квартиру на зоны» (номер зоны + площадь);
  - пользователь отвечает по каждому примеру.
- Сейчас приоритет — **корректное деление на зоны**, а не названия комнат.
- **Главная инструкция пользователя (не выполнена до конца, см. ниже):** если на плане БТИ
  помещения залиты разными цветами (санузел одним, каждая комната своим), зона = цвет, и всё.
  Только если цвета нет — делить по линиям.
- Сантехника, мебель, полотна дверей и цифры **не должны** задавать границы зон. Границы задают
  жирные стены; идея пользователя — «по углам, прямоугольниками до стен».
- Пример 17 (`bench/plans/net15`) выверен с пользователем. Правильно — 7 зон:
  - левая комната;
  - центральная комната;
  - коридор от входа до санузла;
  - ванна;
  - туалет (раздельно с ванной — решение пользователя «(А)»);
  - кухня;
  - балкон-трапеция.

  Не ломайте его.

Порядок шагов в `quickPlanCore` (`app/src/quick/index.ts`):

1. **Бумага и преграды.** Бумага — самый частый светлый тон; всё остальное — преграда. Цветная
   заливка пола (`floorBin`) не считается преградой. Карта цветов пола — `cls`.
2. **Затравки комнат и масштаб.**
   - Затравки — открытием свободного пространства ~0,9 м плюс мелкая затравка 0,6 м для санузлов
     с сантехникой.
   - Метка не растёт на пол другого цвета.
   - Масштаб берётся по площади квартиры (`areaM2`) или по ширине комнат.
3. **Чистка зон.** Мелкое склеивается; квартира отделяется от поля листа; «ничейный» пол (3б)
   становится помещением.
4. **3в — цветные зоны.** Пятно одного цвета — зона. Если в пятне несколько помещений, найденных
   по стенам, оно делится между ними.
5. **4 — проёмы.** Двери-разрывы, двери-чёрточки, вход, окна.
6. **5 — полигоны.**
   - Предметы внутри комнаты отдаются комнате; сюда входит порог толщины линий
     `strokeThreshold` по самому плану.
   - Углы, вырезанные цифрами, дозаполняются.
   - Скошенные стены — длинная лесенка заменяется прямым отрезком.

### 1. `color-first.patch` — «зона = цвет» (то, что просит пользователь)

- Цвета зон берутся прямо с картинки:
  - пики гистограммы светлых цветных тонов;
  - тон бумаги исключён;
  - пиксель относится к ближайшему тону.
- Заливка стен отсекается формой пятна: у зоны есть часть шире 0,5 м.
- **Цветной план** — цветные пятна покрывают ≥ 50 % квартиры. На нём зоны берутся **только по
  цвету**.
- **Один тон > 50 %** (как жёлтый net15) — внутри цвета делим по стенам.
- **Без цвета** — по линиям, как раньше.

Состояние:
- По картинкам: на net17 ванна и туалет стали отдельными зонами; net15 не сломан.
- Первый прогон дал 85,1: желтоватая бумага сканов принималась за цвет на техпланах net18,
  net06, ex4.
- После этого бумага исключена из тонов. По отладке на этих техпланах цветных зон больше нет.
  **Бенч после исправления не прогнан** — это первое, что нужно сделать.
- Известные недочёты на цветных планах:
  - net14: балкон и комната одного цвета сливаются;
