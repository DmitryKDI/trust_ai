# Ручные стены и сохранение перегородок

Изменение 03.10.2026 поверх `2ef21b909d3bb522df9263514e22a0a32f7b304b`.
Основной сценарий заказчика — настольный браузер.

## Почему пропадала перегородка

Растровое распознавание обычно возвращает зоны без отдельных `Wall`.
В схеме с мебелью стены рисуются по свободным промежуткам между контурами зон.
Если граница потеряна или соседние контуры касаются, нужной перегородки может
не быть в изображении. Это не доказательство отсутствия стены на исходнике.

Дополнительно найден общий дефект: условие `g.walls.length` переключало весь
план с границ помещений на явные стены. Первая ручная стена отключала остальные
стены скана и в отображении, и в валидаторе. Исправлено сохранением основы
стен `wallMode = rooms` и добавлением ручных стен к ней.

## Как исправить план

1. На экране вариантов раскройте «Быстрая правка плана», нажмите «Стена».
2. Выберите тип: «Несущая», «Перегородка» или «Тип неизвестен». Укажите
   толщину в миллиметрах. Тип задаёт пользователь, автоматического вывода
   о несущей функции по цвету или толщине нет.
3. Щёлкайте начало и углы полилинии, затем нажмите Enter — все сегменты
   появятся одним действием. Shift выравнивает сегмент по предыдущей точке;
   Esc отменяет черновик. Ctrl+Z убирает последнюю точку при рисовании
   или отменяет всю готовую полилинию. Доступны кнопки завершения и отмены.
4. Щёлкните готовую стену, чтобы изменить тип/толщину или удалить её клавишей Delete.
   Для изменения положения удалите и нарисуйте заново. Доступны отмена/повтор.
5. При необходимости добавьте дверь. Стена не меняет контуры и назначения
   зон автоматически: для отдельной зоны используйте «Разрезать» или обведите
   помещение на шаге «Разметка».
6. Пересоберите варианты. Старая мебель помечается устаревшей; новая генерация
   и валидатор учитывают ручную стену как препятствие.
7. Проверьте границы, проёмы и масштаб, затем сохраните проверенный план
   в блоке обучения. При повторной загрузке того же файла/страницы сохраняются
   положение, толщина, тип стены и основа стен скана.

Полный редактор на шаге «Разметка» сохраняется: цепочка стен по точкам,
векторная заливка с чертежа, тип, толщина, размерная привязка, проёмы.
Добавление стены в нём тоже сохраняет основу растрового плана.

Флажок «Использовать границы зон как основу стен» позволяет вернуть основу
старого скана с ранее добавленными ручными стенами. Отключайте его, если
все стены описаны отдельно и границы зон не должны создавать дополнительные
препятствия. Изменение этого флажка тоже требует пересборки мебели.

## Отображение и расчёт

На схеме с мебелью несущая стена тёмная, перегородка светлее, неизвестный
тип имеет штриховку. Цвета соответствуют выбранному стилю плана. Ручная
стена видна и поверх «Оригинала БТИ», где сохраняется исходное изображение.
В полном/быстром редакторе ручные стены выбираются отдельно от зон.

Для скана расчётные препятствия объединяют прежнюю геометрию вне помещений
и явные стены с вырезанными проёмами. Сетка доступа закрашивает явные стены,
сохраняя внутренние кольца и проёмы. Добавление первой стены не отменяет
расширение проёмов, необходимое для связи зон скана.

`PlanGeometry.wallMode` — необязательное поле `rooms | explicit`. Старый
JSON без этого поля сохраняет прежний выбор по наличию стен. При первой
ручной стене на плане с зонами и без стен режим фиксируется как `rooms`.
Он сохраняется при удалении стен, отмене, масштабировании и экспорте.
Режим включён в хэш геометрии. Формат проекта и IndexedDB не изменены.

Сохранённый пример обучения включает всю геометрию стен. Передача исправлений
на новые изображения и обучение определения несущих стен не реализованы.
Для этого нужны размеченные контуры/стены и отдельная оценка обобщения.
Неизвестный масштаб остаётся оценочным, толщина и размеры требуют калибровки.

## Проверка

```bash
cd app
npm run build -- --base=/trust_ai/
npx vitest run --exclude tests/bench.test.ts --maxWorkers=1
npm run bench
npx playwright test --config=playwright.production.config.ts
npx playwright test
```

`manual-walls.test.ts` проверяет сохранение прежних препятствий после первой
стены, пересечение мебели, блокировку и открытие прохода дверью, сохранение
стен в примере обучения и растеризацию геометрии с отверстиями.
Production e2e добавляет перегородку между двумя санузлами на открытом net15,
меняет её тип, пересобирает мебель, проверяет четыре стиля и повторную загрузку.
Это проверка редактора, не автоматический эталон определения несущих стен.

Результат 03.10.2026: типы/сборка проходят; 73 unit passed / 27 skipped,
обычный e2e 5 passed / 5 skipped, production e2e 5 passed / 1 skipped.
33-плановый бенч повторён: `0.8792958873172777`, исходный порог
`0.8691096089491812` сохранён. В production-примере также вручную удалена
ложная дверь на сплошной перегородке санузлов; память сохраняет её удаление.
Причины ложных автоматических проёмов ещё требуют отдельного исправления.
