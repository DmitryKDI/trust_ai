# Траст ремонт — передача проекта в Claude Code

## Что это за проект

Предпродажный планировщик квартиры для менеджера компании «Траст ремонт». Менеджер получает план и короткий бриф, показывает клиенту три предварительных сценария планировки, мини-концепцию интерьера и ориентир по стоимости работ **до** подготовки подробной сметы. Цель — продавать экспертное решение, а не конкурировать только итоговой цифрой.

Текущая опубликованная демоверсия: приватный сайт владельца (адрес убран из публичной копии).

Отдельный автономный файл для согласования лежит в `outputs/trust-remont-prototype.html`; **не редактируй его как исходник**, он собран из `dist/index.html` и содержит встроенные изображения и шрифты.

Если работа ведётся на другом компьютере, распакуй `trust-remont-source.zip` и работай с его `dist/index.html`.

## Что уже работает

- Кликабельный путь: новый проект → загрузка плана → бриф → анализ → три сценария → мини-концепция → клиентская страница.
- Редактирование брифа и выбор сценария, который переносится в клиентский экран.
- Планы в SVG: мебель, окна, двери, мокрая зона. Палитра чертежа светлая и графитовая; интерфейс вокруг — молочно-шоколадный.
- Демо-квартира 82 м², семья с ребёнком, две спальни.
- Предварительный ориентир по **работам** 35–40 тыс. ₽/м²; при 82 м² это 2,87–3,28 млн ₽. Материалы и комплектация отдельно. Это не смета и не коммерческое обязательство.
- Печать клиентской страницы через системную печать браузера.

## Что сейчас является только демонстрацией

- Выбор файла сохраняет только имя файла. PDF/JPG/PNG **не распознаётся**, не загружается на сервер и не влияет на геометрию.
- Анализ стен, окон, дверей и мокрых зон — заранее подготовленный пример, а не результат анализа файла.
- Три сценария — заранее нарисованные расстановки на одной демо-квартире. Генератора планировки ещё нет.
- Визуальные референсы в исходнике загружаются по внешним URL. В автономном файле для согласования они встроены.
- CTA на клиентской странице пока показывает сообщение; заявки или CRM-интеграции нет.
- Хранения проектов, пользователей, PDF-экспорта, проверки строительных норм, реальной сметы нет.

Никогда не называй демо-анализ распознаванием загруженного плана. Не выдавай условную схему за обмерный чертёж или пригодное к реализации проектное решение.

## Требования к продукту после согласования концепции

1. **Ввод плана.** Принимать PDF/JPG/PNG, показывать оригинал, сохранять привязку к проекту. Распознавать контур, несущие стены, перегородки, окна, двери, мокрые зоны и размеры. Если масштаб или элемент неоднозначен, менеджер должен подтвердить или поправить его вручную. Без подтверждённых размеров не рассчитывать габариты как точные.
2. **Структурированная модель.** Хранить геометрию в реальных единицах (мм), назначение помещений, запрещённые изменения, проёмы и связи между комнатами. Разделить исходный план, допущения и предложенные изменения.
3. **Расстановка.** Использовать мебель с реальными габаритами и узнаваемым видом сверху. Кровать — изголовьем к стене, кухня — по рабочей стене с учётом мокрой зоны, шкафы — у стен, столы — с доступом к сидениям. Предметы не должны пересекать стены, двери, зоны открывания, проходы, окна и друг друга. Проверять доступ к помещениям. Если вариант не помещается, не рисовать его как допустимый.
4. **Три осмысленных сценария.** «Больше пространства», «Максимум хранения», «Семейный» должны действительно различаться размещением и приоритетами, сохраняя один исходный контур и ограничения. Показывать короткое объяснение решений и неопределённости.
5. **Мини-концепция.** Палитра, материалы, стиль, 2–4 визуальных ориентира, привязанные к выбранному сценарию. Не подменять план интерьерной красивой картинкой.
6. **Предварительная стоимость.** Отдельно показывать работы, материалы и допущения. Диапазон работ 35–40 тыс. ₽/м² — исходная демонстрационная ставка, которую владелец должен иметь возможность изменить. Не смешивать её с указанным в демо-брифе общим бюджетом 12–15 млн ₽. Подробная смета — следующий этап после интереса клиента.
7. **Клиентская подача.** Чистая страница без акцента на ИИ: план, преимущества, стиль, прозрачный предварительный диапазон и CTA к полноценному дизайн-проекту. Экспорт в файл для отправки клиенту.

Сохраняй премиальный минимализм, молочно-шоколадную оболочку и нейтральный чертёж. Не возвращай прямоугольники и кружки вместо мебели. Не копируй чужие интерфейсы или чужие мебельные модели напрямую; делай собственные понятные обозначения.

## Рабочий порядок для Claude Code

1. Прочитай этот файл, `dist/index.html` и применимые локальные инструкции `AGENTS.md`, если они есть.
2. Сначала опиши текущую архитектуру и ограничения по исходнику. Не предполагай, что за красивым интерфейсом уже есть ИИ или сервер.
3. Согласуй с владельцем минимальные входные данные для реального MVP: 1–3 обезличенных исходных плана с размерами, правила компании по допустимым решениям, набор типовой мебели с габаритами, рамки стоимости и материалы. Не проси реальные данные клиентов, если для проверки хватит обезличенных.
4. Реализуй первое рабочее вертикальное сечение: один реальный план → подтверждение геометрии → один валидный сценарий → проверка пересечений и проходов → клиентский результат. Затем добавляй ещё два сценария.
5. Извлеки модель плана и мебельных элементов из длинной HTML-строки в поддерживаемые файлы, когда начнёшь реальную реализацию. Не переписывай весь интерфейс ради смены стека, пока это не необходимо.
6. Проверяй геометрию содержательными тестами: пересечения, открывание дверей, ширина проходов по согласованным правилам, отсутствие размещения мебели за пределами комнат, одинаковый исходный контур для сценариев. Визуально проверь крупный план, карточки трёх сценариев, клиентскую страницу и мобильную ширину.
7. Перед завершением каждого этапа перечисляй, что реально работает, что остаётся демо, как запустить и что нужно от владельца.

Не подключай платный API, Supabase, n8n, WeWeb, CRM или публикацию для внешних клиентов без отдельного решения владельца о доступах и расходах. Это возможные компоненты, а не уже утверждённая архитектура. Текущий HTML можно развивать локально, пока заказчик согласует концепцию.

## Критерии готовности MVP

- На новом, не зашитом в код плане менеджер может подтвердить масштаб и ключевую геометрию.
- Все три варианта основаны на этом плане, визуально различаются, содержат мебель с габаритами и проходят проверки пересечений и доступа.
- При невозможном требовании интерфейс объясняет причину, а не рисует неправдоподобный вариант.
- Клиентская страница указывает источник исходных данных, допущения и предварительный характер цены.
- Загруженный файл не вызывает показ демо-геометрии под видом результата его анализа.
