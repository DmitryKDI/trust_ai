# Траст ремонт — предпродажный планировщик

Приложение для менеджера на компьютере: загрузить план квартиры → проверить и исправить геометрию и назначения зон → получить варианты мебели → подготовить мини-концепцию и страницу для клиента.

Результат — предварительная концепция с проверкой человеком. Автоматическое распознавание может ошибаться; перед показом клиенту нужно проверить границы помещений, стены, проёмы, масштаб и мебель.

## Рабочая ветка

Вся текущая разработка ведётся в **`main`**. В неё перенесена актуальная версия приложения с сохранением истории.

Для продолжения разработки сначала прочитайте [AGENTS.md](AGENTS.md): правила комплексных правок, инструменты, сохранность данных, проверки и выпуск. Затем используйте [docs/HANDOFF.md](docs/HANDOFF.md) и [docs/TZ.md](docs/TZ.md). Их старые разделы описывают историческое состояние; актуальное поведение сверяйте с кодом и проверками конкретного SHA.

## Приложение для Windows

Настольная версия запускается через **Траст ремонт — Планировщик** в меню «Пуск» или с ярлыка на рабочем столе. Браузер, батник, сервер, Node.js и Git для работы не нужны. Установщик для Windows 10/11 x64 создаётся workflow **Windows application**. Проверенные выпуски доступны в [GitHub Releases](https://github.com/DmitryKDI/trust_ai/releases/latest); установленная программа обновляется через «Справка → Проверить обновления».

Установка выполняется для текущего пользователя без прав администратора. Проекты, исходные планы и обучение остаются в `%APPDATA%\TrustRemontPlanner`. Повторная установка поверх прежней версии использует то же хранилище. Удаление программы не очищает проекты. Для переноса из браузерной версии сохраните резервную копию каждого проекта в JSON и импортируйте её в новом приложении; отдельную память обучения переносите через «Экспорт обучения» / «Импорт обучения». Проекты другого браузерного профиля автоматически не копируются.

Кнопка **Сохранить PDF** на странице клиента открывает обычное окно сохранения Windows. Резервные копии и каталоги также сохраняются через системное окно. Перед закрытием приложение завершает автосохранение; если сохранение не удалось, предлагает вернуться в проект. Интернет для локальной разметки, вариантов и 3D не нужен. В Windows-программе внешние изображения по ссылкам автоматически не загружаются: добавьте файл изображения. Канал обновлений использует отдельную сетевую сессию.

Для разработки настольной версии: `cd app`, `npm ci`, `npm run desktop:start`. Для установщика на Windows: `npm run desktop:package`. Перед полной проверкой `.exe` соберите установщик и тестовую следующую версию (`npm run desktop:fixture`), затем выполните `npm run desktop:test`. Тестовый установщик не публикуется. Установщик пока без цифровой подписи. Проверка и установка обновлений реализованы; контрольная сумма не заменяет подпись издателя. Ограничения защиты описаны в [отчёте](docs/security-hardening-2026-10-14.md).

## Прежний запуск через браузер (Windows)

**Простой запуск на Windows 10/11 (64 бит):** скачайте и распакуйте весь репозиторий рабочей ветки либо обновите существующую копию. Дважды щёлкните **`Запустить планировщик.bat`** в корне проекта.

Батник проверяет Node.js 24 и npm. Если они отсутствуют, повреждены или версия Node.js отличается, скачивает официальный архив с nodejs.org, проверяет SHA-256 и устанавливает Node.js вместе с npm в `%LOCALAPPDATA%\TrustRemontPlanner\runtime`. Права администратора не нужны; системные установки и PATH не меняются. Используется встроенный Windows PowerShell 5.1.

Затем проверяются зависимости проекта; при первом запуске, после изменения `package.json`/`package-lock.json` или при неполной установке выполняется `npm ci`. Браузер открывается при запуске сервера. Окно батника нужно оставить открытым; остановка — Ctrl+C. Окно CMD остаётся открытым и после завершения запуска, включая ранние ошибки PowerShell. Журнал запуска записывается в `%TEMP%\TrustRemontPlanner-start.log`; при сбое пришлите этот файл или текст ошибки из окна. Если порт 5190 занят, закройте прежнее окно сервера и повторите запуск.

Для установки Node.js и зависимостей нужен интернет. При исправных установленных компонентах повторный запуск не требует скачивания. Git, Python, Docker и отдельно установленные React/Vite для этого запуска не нужны. **Не переносите один батник отдельно:** рядом должны оставаться `scripts/start-planner.ps1` и остальные файлы проекта.

После обновления репозитория достаточно снова запустить батник. Приложение открывается по прежнему адресу `http://127.0.0.1:5190`, поэтому локальные проекты браузера остаются доступны.

Для запуска вручную нужны Git (для клонирования и обновления) и [Node.js](https://nodejs.org) 24. Эта версия используется и в workflow сборки.

При первом запуске выполните в PowerShell или терминале:

```powershell
git clone --branch main --single-branch https://github.com/DmitryKDI/trust_ai.git
cd trust_ai/app
npm ci
npm run dev
```

Откройте [http://127.0.0.1:5190](http://127.0.0.1:5190). Терминал с запущенным сервером должен оставаться открытым; остановка — Ctrl+C.

Если репозиторий уже скачан, остановите сервер и из корня `trust_ai` выполните:

```powershell
git switch main
git pull --ff-only origin main
cd app
npm ci
npm run dev
```

## Основной сценарий

1. **Создать проект.** При каждом запуске и обновлении страницы открывается пустая форма нового проекта. Введите псевдоним клиента. Сохранённые проекты открывайте вручную кнопкой «Открыть»; автозагрузки последнего проекта нет.
2. **Загрузить план.** Поддерживаются PDF, JPG и PNG, а также вставка картинки через Ctrl+V. Для многостраничного PDF выберите нужную страницу. Общая площадь помогает определить масштаб; условный масштаб нужно проверить или откалибровать вручную.
3. **Построить предварительные варианты.** Программа распознаёт план и пытается получить три сценария: «Больше пространства», «Максимум хранения», «Семейный». Они могут требовать доработки.
4. **Проверить и исправить план.** На экране вариантов используйте «Быструю правку плана», для сложных контуров — шаг «Разметка».
5. **Назначить помещения.** Проверьте, где кухня, ванная, туалет, гостиная, спальня, коридор и остальные зоны.
6. **Пересобрать мебель.** После изменения границ, стен, проёмов или назначения старые варианты могут быть устаревшими. Нажмите «Пересобрать варианты по исправленному плану», «Пересобрать варианты с новыми назначениями» или общую кнопку «Пересобрать варианты».
7. **Проверить результат.** Прочитайте нарушения и предупреждения. Мебель можно передвигать, поворачивать клавишей R, удалять клавишей Delete и добавлять из списка.
8. **Подготовить показ клиенту.** Укажите бриф, палитру, материалы и референсы; утвердите подходящий вариант для страницы клиента и печати/PDF.

## Оригинал и расчётная схема

В режиме правки **оригинальный план служит подложкой**. Поверх него отображаются зоны, стены и проёмы программы. Исходная картинка не меняется.

Видимая на исходнике стена ещё не означает, что программа её распознала. Для расстановки и проверок используется структурированная геометрия с вашими исправлениями. Стиль «Оригинал БТИ» показывает исходник под мебелью; остальные стили показывают расчётную схему.

## Ручные зоны и их назначение

На экране вариантов раскройте «Быстрая правка плана»:

| Действие | Инструмент |
| --- | --- |
| Найти пропущенное помещение по свободному полу исходника | «Добавить комнату» |
| Обозначить помещение двумя противоположными углами | «Комната по углам» |
| Разделить слипшиеся помещения | «Разрезать» |
| Собрать соседние части одного помещения | «Объединить» |
| Обвести сложный контур по точкам | «Разметка» → «Помещение по точкам» |

При создании зоны можно сразу выбрать **«Назначение новой зоны»**. Тип существующей зоны меняется в списке «Комнаты», свойствах помещения или кнопках быстрой правки.

Поддерживаются: ванная/совмещённый санузел, туалет, кухня, кухня-гостиная, гостиная, спальня, детская, прихожая, коридор, кладовая/гардероб, балкон/лоджия и «Не определено».

**Смена назначения не меняет границы зоны.** Если автоматический тип верный, его можно явно подтвердить кнопкой «Подтвердить назначение». После изменения типа пересоберите мебель.

## Ручные стены и проёмы

1. В «Быстрой правке плана» нажмите **«Стена»**.
2. Выберите тип: несущая, перегородка или неизвестный. Укажите толщину в миллиметрах.
3. Щёлкайте начало и каждый следующий угол полилинии. **Enter** создаёт все сегменты стен одним действием; **Esc** отменяет черновик. Для двух точек получается одна стена, для четырёх — три. **Shift** выравнивает очередной сегмент горизонтально или вертикально относительно предыдущей точки. Это работает и в быстрой правке, и в полном редакторе. Можно использовать кнопки «Завершить стены (Enter)» и «Отменить рисование (Esc)».
4. **Ctrl+Z** во время рисования убирает последнюю точку; после подтверждения отменяет всю полилинию. **Ctrl+Y** возвращает её. **W** включает стены, **V** — выбор. **Delete** удаляет выбранную стену, дверь, зону или предмет мебели в активном редакторе. При вводе текста клавиши редактируют текст.
5. Выберите готовую стену, чтобы изменить тип/толщину или удалить её. Углы выбранной стены можно перетаскивать; угол также задаётся числом в свойствах. Доступны отмена и повтор.
6. Добавьте или исправьте дверь, затем пересоберите варианты.

Несущая стена тёмная, перегородка светлее, неизвестный тип имеет штриховку. Тип задаётся пользователем; программа не определяет несущую функцию автоматически.

На сканах ручная стена добавляется к основе стен по границам зон. Флажок **«Использовать границы зон как основу стен»** позволяет сохранить эту основу при дорисовке отдельных перегородок. Если все стены заданы отдельно, основу можно отключить.

**Нарисованная стена не разделяет зону автоматически.** Для разделения границ используйте «Разрезать» или ручной контур. Ложный распознанный проём можно выбрать и удалить; он иначе может оставлять отверстие в стене.

**Двери:** перед добавлением в быстрой правке задайте «Ширина новой двери, мм» и «Створки новой двери». Щёлкните по стене. У выбранной двери можно изменить ширину проёма, выбрать одну или две равные створки и сторону открывания. В полном редакторе два щелчка задают откосы; ширину затем можно уточнить числом. Enter или выход из поля применяет введённый размер. Изменение ширины сохраняет центр проёма. Обе створки учитываются в схеме, проверках и генераторе мебели. Старые двери без параметра створок остаются одностворчатыми.

Полный редактор на шаге «Разметка» также поддерживает стены, проёмы, калибровку, инженерные элементы и помещения. Подробности — [docs/manual-walls.md](docs/manual-walls.md).

## Размеры мебели

Щёлкните предмет на большой схеме варианта. В правой панели появятся **«Ширина предмета, мм»** и **«Глубина предмета, мм»** — для ванны, душа, раковины и остальных предметов. Enter или выход из поля применяет размер. Это размеры самого предмета до поворота; центр и угол поворота сохраняются. Предмет можно отдельно передвинуть мышью и повернуть клавишей R.

Рисунок и расчётный габарит меняются вместе. Пересечения, доступ и открывание дверей проверяются по новым размерам. Правки автоматически сохраняются в текущем варианте; изменение мебели снимает его утверждение. Пересборка вариантов создаёт новую расстановку с типовыми размерами — для сохранения ручных габаритов редактируйте и сохраняйте выбранный вариант. Размеры зависят от калибровки плана.

## Память правок и локальное обучение

Правки сохраняются в текущем проекте автоматически. Чтобы использовать их при повторной загрузке, нужно отдельное действие:

1. Проверьте все границы, стены, проёмы, назначения и масштаб.
2. Раскройте **«Обучение на моих правках»**.
3. Нажмите **«Сохранить проверенный план для обучения»**.

| Ситуация | Что делает программа |
| --- | --- |
| Открытие сохранённого проекта | Использует его текущую геометрию и назначения |
| Повторная загрузка того же файла и страницы с включённой памятью | Восстанавливает сохранённые зоны, стены, проёмы, масштаб и типы; заново рассчитывает мебель |
| Загрузка нового файла | Выполняет обычное распознавание; может предположить тип зоны по ручным примерам |
| Обучение отключено на шаге загрузки | Выполняет обычное распознавание без пользовательских примеров |

Для предположения типа на новом плане нужны близкие согласующиеся примеры минимум из **трёх разных файлов**. Автоматические названия не становятся обучающими метками без ручного выбора/подтверждения. Предположение требует проверки; точность такого подбора на новых реальных планах ещё не измерена.

**Стены и контуры на новые планы не переносятся. Обучение нейросети не выполняется.** Пересохранённое или обрезанное изображение может считаться новым файлом.

Доступны «Забыть эту страницу», «Очистить обучение», экспорт и импорт обучения. Если правка сделана после сохранения примера, сохраните проверенный план повторно, чтобы обновить память.

Инструкция и ограничения — [docs/local-learning.md](docs/local-learning.md).

## Сохранение и перенос

Проекты, исходные файлы и примеры обучения хранятся локально в браузере. Обработка планов и память правок не требуют отправки документов на сервер.

Для переноса проекта: **«Все проекты» → «Резервная копия» → «Импорт из JSON»** на другом компьютере. Копия включает исходники и связанные с проектом примеры обучения. Для переноса всего набора примеров используйте **«Экспорт обучения» / «Импорт обучения»**.

Старые проекты JSON version 1 поддерживаются. Обновление базы браузера сохраняет прежние проекты и файлы. Память обучения ограничена 200 страницами и 5 МБ; при заполнении удаляются старейшие примеры. Перед очисткой данных браузера сохраните резервные копии.

## Ограничения и качество

- Контуры, назначения и проёмы могут распознаваться неверно. Ложные двери/окна и пропущенные перегородки требуют проверки.
- Масштаб без надёжной калибровки оценочный. Типовые размеры мебели не подтверждают размеры квартиры.
- Генератор стремится получить три варианта, но не гарантирует три допустимых и полных решения на любом плане.
- Проверки проходов, подходов и стоимости используют правила проекта. Это не строительная документация, согласование перепланировки или точная смета.
- Стояки на плане могут отсутствовать; положение мойки тогда требует проверки.
- Данные примеров служат для регрессии; распознаватель не должен содержать исключения по имени конкретного плана.

Последний зафиксированный прогон 03.10.2026 на версии `0896b82`: 73 unit-теста прошли, 27 пропущены; обычный e2e — 5 прошли / 5 пропущены; production e2e — 5 прошли / 1 пропущен. Бенч на 33 планах — **87,93/100**, исходный порог — **86,91/100**.

Этот бенч проверяет преимущественно площади, некоторые количества и расстановку. Его балл не является точностью контуров или назначения помещений. Полная приёмка ТЗ ещё не выполнена.

Отчёты: [bench/report.md](bench/report.md), [docs/fix-zones-2026-10-03.md](docs/fix-zones-2026-10-03.md), [docs/fix-small-rooms-2026-10-03.md](docs/fix-small-rooms-2026-10-03.md). Устройство распознавания — [docs/recognition.md](docs/recognition.md).

## Публикация в браузере

В рабочей ветке подготовлен workflow GitHub Pages. Само наличие репозитория не означает, что приложение уже доступно онлайн: нужны настройка Pages и успешный deploy. Инструкция — [docs/pages.md](docs/pages.md).

Основной сценарий заказчика — работа на компьютере. Мобильные проверки сохранены в тестах.

## Для разработчика

Стек: Vite, React, TypeScript; тяжёлое распознавание и генерация мебели выполняются в workers.

Команды выполняются из `app`:

```powershell
npm ci
npm run typecheck
npm test
npm run bench
npm run build
npm run e2e
```

Проверка production-сборки с путём репозитория:

```powershell
npm run build -- --base=/trust_ai/
npx playwright install chromium
npx playwright test --config=playwright.production.config.ts
```

Обычный e2e использует установленный Microsoft Edge; переменная `PW_CHROMIUM` позволяет указать другой исполняемый файл Chromium. Production e2e использует Chromium Playwright или `PW_CHROMIUM`. Пропуски тестов и их причины публикуйте вместе с результатами. E2e сохраняет снимки в `docs/screenshots`; не включайте случайные снимки в коммит.

| Папка `app/src` | Назначение |
| --- | --- |
| `model` | Модель геометрии в миллиметрах |
| `recognize` | Выбор пути распознавания, векторный PDF и workers |
| `quick` | Растровое распознавание |
| `geometry` | Контуры, стены, проёмы и операции с полигонами |

## Процедурная 3D-сцена (основа каталога)

На шаге «Мини-концепция» теперь строится объёмная схема по текущим стенам, помещениям и расстановке мебели. Выбирайте любой из вариантов в поле «Вариант для просмотра», вращайте сцену мышью/пальцем, увеличивайте колесом или кнопками. Стрелки и +/− работают после фокуса на сцене. «Сверху» и «Общий вид» возвращают удобные ракурсы.

Высота потолка по умолчанию 2800 мм, двери 2100 мм, окна 1400 мм, подоконник 900 мм (явная высота из разметки имеет приоритет). Обзорный разрез уменьшает стены до 700 мм, чтобы мебель была видна; доступны полная высота стен и потолок. Размеры и поворот мебели берутся из редактора. «Высоты мебели» изменяет высоты по типам предметов. Это условные формы, а не точные модели изделий; качество зависит от масштаба и корректности плана. Стены распознанного скана строятся по контурам помещений, исходная фотография плана в 3D не используется.

Каталог пока пуст, используются базовые цвета. В разделе «Каталог материалов» скачайте JSON-шаблон, заполните и импортируйте его. Формат: `{"version":1,"materials":[{"id":"oak","name":"Дуб","category":"floor","color":"#c9ad8e","tileWidthMm":1200,"tileHeightMm":200,"article":"A-1","price":2500,"unit":"м²"}]}`. Категории: `wall`, `floor`, `tile`, `wood`, `fabric`, `ceramic`, `metal`, `glass`. Выбранные материалы применяются ко всем поверхностям соответствующего типа во всех вариантах текущего проекта. Текстуру PNG/JPEG/WebP до 3 МБ можно прикрепить после импорта или указать в поле `textureDataUrl` (data URL). Размеры повторения задаются в мм; цена справочная и автоматически в смету не включается. Максимум 100 материалов и 12 МБ на JSON. Импорт заменяет каталог текущего проекта, неверный JSON ничего не меняет.

Настройки, каталог, локальные текстуры и сохранённые ракурсы входят в проект, автосохранение и JSON-экспорт. «Сохранить ракурс» добавляет изображение в концепцию и на страницу клиента (до четырёх изображений). При изменении плана/материалов сохранённый ракурс нужно переснять. Новые проекты больше не заполняются тремя фотографиями-заглушками; при открытии концепции старого проекта удаляются только эти встроенные изображения. Собственные референсы остаются. Сборка сцены работает локально, без API и внешних 3D-моделей; требуется WebGL в браузере.


### Редактор и клиентская концепция

- Shift + щелчок выбирает несколько стен, проёмов, зон или предметов мебели. Для одной категории доступна общая смена типа; группа правок отменяется одним Ctrl+Z.
- Полилиния стен замыкается при щелчке рядом с начальной точкой. У выбранной фигуры можно двигать углы; угол стены также задаётся числом.
- Мебель прилипает к поверхности стен с учётом толщины и к соседним предметам. Alt временно отключает прилипание. Белые маркеры на сторонах и углах меняют размер с неподвижной противоположной стороной; числовой ввод сохраняется.
- В мини-концепции есть готовые стили и задачи клиента: мало места, недостаток света, простой уход, дети/питомцы, бюджет, уют. Подбор заполняет согласованную палитру, предлагаемые материалы и обоснование. Случайный стиль и другая сочетающаяся палитра отражаются в 3D; назначенные материалы заказчика сохраняют приоритет.
- «Пересобрать этот вариант» заменяет только выбранную карточку. «Пересобрать все варианты» ищет новую тройку. Поиск меняет предпочтение допустимых позиций, сохраняя правила и проверки; если альтернативы не найдены, прежние решения сохраняются.
- Презентация клиента показывает до трёх готовых актуальных вариантов с отдельными 3D-визуализациями и планами; рекомендуемый отмечен. 3D автоматически сохраняется в изображения для печати/PDF. Если план допускает меньше трёх безопасных решений, приложение сообщает об этом и не дублирует одну расстановку.

## Обновления Windows-программы

Начиная с 0.2.2 программа проверяет стабильные выпуски GitHub Releases при запуске. В меню «Справка → Проверить обновления» и в панели «Обновления» доступна ручная проверка. Новая версия скачивается только по кнопке; после проверки SHA-512 появляется «Установить и перезапустить». Перед установкой программа завершает автосохранение и запись хранилища. Если проект не сохранён, обновление откладывается. Обычное закрытие приложения само не запускает установщик.

Версию 0.2.2 нужно один раз установить поверх 0.2.1: в прежней сборке проверки обновлений ещё нет. Установщики доступны без аккаунта GitHub: https://github.com/DmitryKDI/trust_ai/releases/latest . Хранилище `%APPDATA%\\TrustRemontPlanner` остаётся тем же. Для обновлений нужен доступ к GitHub; при отсутствии сети работа с планами продолжается локально.

При увеличении версии в `app/package.json` и lock-файле workflow `Windows application` собирает установщик, проверяет интерфейс и настоящий переход на новую версию, затем публикует EXE, `latest.yml`, blockmap и контрольную сумму. Существующий выпуск не перезаписывается. Тестовый установщик следующей версии из `release-update-fixture` никогда не публикуется. GitHub-токен доступен только шагу выпуска и не включается в программу.

## Альбомное КП 0.2.5

Экспорт КП использует A4 landscape: фирменную шоколадную обложку с видом квартиры, рекомендацию, три отдельные страницы вариантов с планом и 3D рядом, палитру материалов и бюджет. ## Стыки стен и история 0.2.6

Ручные стены привязываются к осям и конечным узлам. Близкие стыки (до 120 мм) соединяются вдоль исходных осей при построении стены и поиске комнаты; обозначенные проёмы и более крупные разрывы не закрываются. Для старых планов есть «Соединить углы стен». Автокомната сначала использует векторный контур, затем исходное изображение; ручные стены не требуют скана. Ctrl+Z/Ctrl+Y учитывают русскую раскладку и восстанавливают черновые точки, а правка геометрии сохраняет общие узлы. Проверка прохода остаётся включённой и даёт конкретную подсказку.

## Правая панель и привязка 0.2.7

Свойства объекта и настройки новых элементов в быстрой правке расположены справа от плана. Размеры мебели на экране вариантов также находятся справа. Панель доступна при прокрутке; на узком экране блоки складываются вертикально. При рисовании и правке углов точки притягиваются к вершинам и сторонам геометрии всех источников, включая непроверенные результаты распознавания. Для стен ось явной стены приоритетнее грани комнаты; Shift задаёт строгую ортогональ, Alt при перемещении угла отключает привязку.

## Горячие клавиши 0.2.8

Буквы на кнопках инструментов работают независимо от русской или английской раскладки; полный список доступен под панелью инструментов в «Горячие клавиши». В обоих редакторах V — выбор, H — рука, W — стена, D — дверь. В быстрой правке A — автокомната, N — комната по двум углам, P — контур комнаты, X — разрезать, M — объединить. В разметке C — масштаб, O — окно, S — стояк, F — инженерный элемент, Z — мокрая зона, R — автокомната, N — контур; P/G читают стену/дверь с векторного чертежа, когда он доступен. В редакторе мебели R поворачивает выбранные предметы. Пробел удерживается для временного перемещения плана. Текстовые поля не перехватываются.
