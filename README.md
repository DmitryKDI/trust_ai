# Траст ремонт — предпродажный планировщик

Внутренний инструмент менеджера: загрузить план квартиры → разметить геометрию поверх оригинала → получить 2–3 проверенных варианта расстановки → мини-концепция → страница для клиента с ориентиром стоимости работ.

Это предпродажная концепция с проверкой человеком, а не рабочая документация, согласование перепланировки или смета.

## Открыть с телефона

В рабочей ветке подготовлена публикация через GitHub Pages:
инструкция первого включения — [docs/pages.md](docs/pages.md).
Сайт становится доступен только после включения Pages и успешного deploy;
одного наличия кода в репозитории недостаточно.

## Запуск (Windows)

1. Установите [Node.js](https://nodejs.org) версии 20 или новее.
2. Откройте терминал в папке проекта и выполните:

```bash
cd app
```

```bash
npm install
```

```bash
npm run dev
```

3. Откройте в браузере http://127.0.0.1:5190

Проекты хранятся в браузере (IndexedDB) и открываются после перезапуска. Для переноса на другой компьютер: «Все проекты» → «Резервная копия» (JSON с исходными файлами) → на другом компьютере «Импорт из JSON».

## Как пользоваться

1. **Проект** — «Все проекты» → «Создать проект» (псевдоним клиента).
2. **Загрузка** — перетащите план БТИ, обмер или план застройщика (PDF, JPG, PNG) или вставьте картинку из буфера (**Ctrl+V**). Если на плане нет размерных цифр (скан, фото, скриншот), впишите общую площадь квартиры — по ней определяется масштаб.
3. **«Построить варианты»** — программа сама читает план (стены, окна, двери, комнаты) и сразу показывает 2–3 варианта расстановки мебели: «Больше пространства», «Максимум хранения», «Семейный».
4. **Варианты** — мебель двигается мышью, R — поворот, Delete — удалить, можно добавить предмет; проверки проходов и дверей пересчитываются сразу. Неверное назначение комнаты — поменять в списке «Комнаты» и пересобрать. Неверная стена или дверь — «Поправить план»: редактор поверх оригинала (стены и двери щелчком по чертежу, калибровка, помещения).
5. **Бриф** (по желанию) — состав семьи, работа из дома, стол на сколько мест.
6. **Мини-концепция** — палитра, материалы, картинки-референсы (тоже Ctrl+V).
7. **Для клиента** — утверждённый вариант, польза, ориентир стоимости с перечнем «входит / не входит», «Печать / PDF».

Как программа читает план и насколько точно — `docs/recognition.md`.

**Обучение на ваших правках:** при ручном обозначении зоны выбирайте её
назначение. Проверьте границы и проёмы, затем раскройте «Обучение на моих
правках» и сохраните проверенный план. Повторная загрузка того же файла
восстановит исправления; на новом плане назначения могут предполагаться
по нескольким согласующимся ручным примерам. Контуры на новые файлы не
переносятся. Инструкция, перенос обучения и ограничения —
[docs/local-learning.md](docs/local-learning.md).

**Ручные стены:** «Быстрая правка плана» → «Стена» → тип и толщина →
два щелчка по оси стены → пересобрать мебель. Несущая, перегородка и
неизвестный тип различаются на схеме. Сохранение проверенного плана
запоминает и стены. Инструкция — [docs/manual-walls.md](docs/manual-walls.md).

Кнопка «Правила» — рабочие допущения (проходы, зоны перед мебелью, ставка ₽/м²). Значения по умолчанию лежат в `config/rules.default.json`; это допущения, а не нормативы.

## Что работает и что нет

- **Работает:** всё перечисленное выше, проверки коллизий, дверей, окон, проходов и подходов, сохранение и резервная копия.
- **Не делается:** перепланировка, точная смета. Чтение сканов и фото — приблизительное (см. `docs/recognition.md`), результат правится вручную. Стояки на обмерах часто не обозначены — тогда положение мойки помечается «требует проверки».
- **Ставка** 35–40 тыс. ₽/м² и её состав — демо-допущения до ответа владельца.

## Для разработчика

```bash
npm test
```

```bash
npm run e2e
```

- `npm test` — Vitest: геометрия, валидатор, движок, редактор. Тесты на реальных кейсах пропускаются, если нет `data/cases/*/geometry.json`.
- `npm run e2e` — Playwright на установленном Microsoft Edge: сквозной путь на демо-квартире, десктоп и 375 px. Скриншоты сохраняются в `docs/screenshots/app-*.png`.
- Подготовка страниц больших PDF (нужен Python и `pymupdf`): `python scripts/extract_pages.py` → `data/cases/<кейс>/pages/` и `manifest.json`.

Структура `app/src`:

| Папка | Что внутри |
| --- | --- |
| `model` | Модель данных (мм) |
| `geometry` | Полигоны, стены, проёмы, автоконтур |
| `validate` | Проверки и проходимость |
| `layout` | Шаблоны, движок, варианты, воркер |
| `furniture` | Габариты и символы мебели |
| `pdf` | pdf.js и векторы для привязки |
| `editor` | Операции разметки |
| `screens` | Экраны |
| `storage` | IndexedDB |

## Данные клиентов

Исходные PDF, извлечённые страницы, разметка и отчёты по кейсам (`data/`), ассеты и выходные файлы не коммитятся (`.gitignore`). Материалы клиентов не публикуются без разрешения владельца. Документация: `docs/audit.md`, `docs/skills-research.md`, `docs/pilot-comparison.md`, `docs/portability.md`.
